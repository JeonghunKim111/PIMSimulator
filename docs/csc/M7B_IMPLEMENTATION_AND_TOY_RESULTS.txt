1. IMPLEMENTED SYSTEM BOUNDARY
==============================

The completed production path is:

  CSC descriptor compute
  -> BG-local associative Bank Group Accumulator (BGA)
  -> stable BGA output port
  -> bounded output-destination reserve/accept/commit transfer
  -> 8-byte architectural partial-result records
  -> BG-local 32-byte full/tail burst packing
  -> bounded modeled partial-result writeback
  -> topology-sized resident burst buffers
  -> POST_WRITEBACK host readback
  -> channel-local deterministic read arbitration
  -> bounded host return queue
  -> deterministic indexed FP32 host reduction
  -> authoritative final-y
  -> endToEndSpMVComplete()
  -> resultValid()
  -> finalResult()

The production output mode is:

  CSCBGAOutputConsumerMode::PARTIAL_RESULT_WRITEBACK

EXTERNAL remains an explicit external-consumer mode with no automatic drain.
VALIDATION_ROUND_ROBIN remains an M7A correctness/oracle mode and is not a
production result source.

3. M7B-1: OUTPUT DESTINATION CONTRACT
=====================================

The BGA and descriptor engine do not know the concrete output destination.
Ownership transfer follows:

  BGA output peek
  -> destination capacity reservation
  -> acceptBGAOutput()
  -> destination commit

If source acceptance fails, the destination reservation is cancelled. If the
destination cannot reserve bounded capacity, the BGA front output remains stable
and is not consumed. Commit/cancel form a no-throw ownership boundary.

This boundary permits a future output consumer, including a future logic-die
accumulator, without changing the BGA primitive or descriptor producer.


4. M7B-2: PARTIAL-RESULT WRITEBACK
=================================

Architectural physical record:

  uint32_t row_idx
  float    value

Physical record size is exactly 8 bytes. Simulator-only envelope metadata
includes global BG, generation, output sequence, contribution count, and BGA
output reason. Shadow metadata is not counted as transferred bytes.

Each global BG has an independent bounded packer:

  4 records x 8 bytes = one 32-byte full burst

A final packer containing 1-3 records produces one 32-byte tail burst after the
generic producer/final-drain lifecycle proves no more output can arrive. Padding
does not create fake records or contributions.

The write path contains bounded pending state, bounded in-flight transactions,
and bounded resident buffers. Destination buffer space is reserved at write
issue, so completion cannot fail because the resident buffer became full.
Rank-local write issue uses deterministic round-robin arbitration.

This is a modeled partial-result writeback timing path. It is not a claim that
partial results are persisted in a physical DRAM array.


5. M7B-3: HOST READBACK
======================

Readback policy is POST_WRITEBACK:

  all outputs accepted and retired
  -> all tails flushed
  -> all writes completed and resident
  -> partialWritebackComplete()
  -> host readback begins

Resident ownership follows:

  RESIDENT
  -> READ_IN_FLIGHT
  -> read completion
  -> commit into a pre-reserved host return slot
  -> resident slot FREE

The resident slot is not released at read issue. Host return capacity is
reserved at issue, preventing completion-time queue overflow.

Each channel has independent deterministic round-robin arbitration. Simultaneous
completions use the stable order:

  completion cycle
  -> channel
  -> rank
  -> local BG
  -> writeback burst sequence
  -> record index

Read completion at cycle G becomes downstream-visible no earlier than G+1.


6. M7B-4: DETERMINISTIC HOST REDUCTION
======================================

Returned bursts are accepted atomically only when the bounded reduction queue
has room for every valid record in the burst. A burst is never partially
transferred.

The reducer preserves the authoritative host-visible ordering. It uses bounded
queue and operation state and performs indexed arithmetic directly into:

  std::vector<float> final_y_fp32

Each record performs an ordered float addition:

  final_y_fp32[row] =
      static_cast<float>(final_y_fp32[row] + record.value);

There is no double accumulator followed by a final float cast. Cross-BG records
for the same row and repeated physical records from one BG are both accumulated
in arrival order.

hostReadbackComplete() means all returned payload has reached the reduction
path. hostReductionComplete() additionally requires the reduction queue and
in-flight arithmetic to drain with record/contribution conservation satisfied.


7. M7B-5: PRODUCTION COMPLETION AND RESULT
==========================================

The authoritative production result is the host-reduced FP32 state. It is not
the M7A validation collector, a double semantic shadow, a BGA-local value, or a
CPU reference calculation.

For PARTIAL_RESULT_WRITEBACK mode, endToEndSpMVComplete() requires:

  bgaComputeSubmitComplete()
  AND bgaDrainComplete()
  AND partialWritebackComplete()
  AND hostReadbackComplete()
  AND hostReductionComplete()
  AND result-state/conservation validation
  AND no sticky error

isDone() uses this end-to-end predicate in production mode. resultValid() becomes
true only after the same production completion. finalResult() rejects access
before validity and then returns the authoritative host-reduced FP32 result.

The complete conservation chain distinguishes physical output records from
contributions:

  physical BGA records
  = packed records
  = readback records
  = reduced records

  accepted contributions
  = BGA output contribution sum
  = writeback contribution sum
  = readback contribution sum
  = reduced contribution sum
  = matrix NNZ for a normal workload


8. BOUNDEDNESS AND BACKPRESSURE
===============================

The following resources are explicitly bounded:

  - output destination reservations
  - per-BG record packers
  - pending write bursts
  - write transactions in flight
  - per-BG resident burst buffers
  - read transactions in flight
  - host return burst queue
  - reduction record queue
  - reduction operation state

Pressure propagates upstream without an unbounded overflow vector:

  reduction pressure
  -> returned-burst consumption stalls
  -> host return reservations fill
  -> read issue stalls

and:

  resident/write pressure
  -> packer reservation fails
  -> BGA output acceptance stalls
  -> stable BGA front output is retained


9. ERROR BEHAVIOR
=================

Invalid row/BG/generation/sequence, duplicate identities, reservation
mismatches, duplicate reads/reductions, malformed bursts, and conservation
failures enter a sticky error state. An error prevents end-to-end completion and
result validity. There is no validation-result or legacy-host fallback.

20. SCOPE AND KNOWN LIMITATIONS
===============================

"SparsePIM-compatible completion" here means that BGA partial results cross an
explicit modeled writeback/readback boundary and are globally reduced by an
indexed deterministic host FP32 model to produce final y.

This implementation does not claim:

  - a logic-die Global Accumulator
  - TSV/internal-bus timing
  - physical DRAM-array partial-result persistence
  - CPU instruction-level timing
  - the complete SparsePIM microarchitecture
  - SparsePIM+ completion
  - STREAMING_READBACK

The current policy is POST_WRITEBACK. All result bursts must fit in the finite
resident buffers before host readback begins. Future matrix measurements should
therefore start with a matrix substantially smaller than cant_csc and perform a
resident-capacity preflight before execution.
